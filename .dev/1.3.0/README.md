# 1.3.0 — 做减法:砍掉内置规则,活动栏退回横排

1.2.0 把权限做成了护盾,把活动栏改成了 VS Code 式的竖排。上手一试,两处都过头了。
这一版只做一件事:**把加多了的东西减回去。**

---

## 一、砍掉内置规则「任何操作都问我」

1.2.0 的推理是:三档模型(逐步确认 / 按照规则 / 完全跳过)里,「逐步确认」可以降级成
列表里的一条内置规则 —— 勾上就等于逐步确认,于是概念从三个减到两个。

推理没错,**落地是错的**:

- **层级乱**。它长在规则列表里,却不是一条规则 —— 它没有触发条件、不参与命中判定,
  在 `decide()` 里是一条 if 直接短路掉所有规则。列表里的其它行是「什么情况下问我」,
  它是「别看情况了,一律问我」—— 同一个清单里放着两种不同层级的东西,人当然会晕;
- **它得处处开特例**。不能删、正文不能改、`compiled` 要硬编码成 true、注入提示词时要
  从规则清单里剔出去单独说一句 —— 一条不是规则的东西挤在规则表里,四个文件都得为它让路;
- **而且没人会用**。每一次工具调用都停下来等人点头,跑三步就烦了。它的真实使用率约等于零,
  却占着整个模型里最显眼的一行。

**结论:整个去掉。** 护盾就是一个开关加一份规则清单,没有第三种东西。

```
盾关(skip)  不问不拦
盾开(rules) 命中你写的规则就停下来问;没命中就放行
```

### 迁移

- 启动时删掉 `rules` 表里 `origin = 'factory'` 的行(1.2.0 种下的那条),
  它是系统种的、不是用户写的,删掉不丢任何用户资产;
- 老库里 `permissionMode = 'ask'` 的迁到 `rules`(盾开)。两者都会拦,
  区别只是新模型按规则拦,不再每次都问;
- `Mode` 类型从三值收成 `"rules" | "skip"`,`decide()` 里那条短路分支一并拿掉。

见 `server/permission/seed.ts`。

## 二、活动栏退回横排

1.2.0 把活动栏改成最左侧 52px 竖排图标条(仿 VS Code),换来的是「能装更多组件」。
问题是**代价比收益大**:

- **太像 IDE**。Mainbench 是工作台不是编辑器 —— 一进来先看见一条开发者工具风格的图标轨,
  气质就跑偏了;
- **复杂度翻倍**。竖排 = 活动栏与面板分离 = 「收起」有了两种含义(收面板 / 收整条),
  点当前图标要收起、点别的要展开、标签栏的汉堡要按侧栏状态显隐 —— 为了一个「能多装几个组件」
  的问题,引入了一串状态耦合;
- **那个问题本来也不急**。横排装到八九个才需要滚动,而实际会钉上活动栏的组件通常三五个。
  真到了那天再说,不必现在为它改架构。

**退回 1.2.0 之前的横排**:侧栏顶部一行标签(空间不足退化纯图标,再溢出横向滚动),
行末 `⋯` 选哪些组件上栏,底部一行设置。`navOpen` 那条 prop 链一并还原 ——
侧栏展开时汉堡在侧栏头部,收起时才出现在标签栏左端。

### 顺带丢掉的

竖排版本上做的**图标状态点**(会话未读/运行亮点、应用在跑亮点)一并撤掉。
它依附于「面板关着图标还在」这个前提,横排下这个前提不存在。

## 三、留下的

1.2.0 不是白做的,这些留着:

- **护盾本身**:输入框那一行的绿/红盾牌按钮、开关、规则清单、两级导航(列表 ⇄ 详情)、
  一句话编译成触发条件、编译不出如实标「只靠自觉,拦不住」;
- **审批卡**:长在对话流里,出口两个(不允许 / 允许这一次);
- **`Switch` 的定位修复**:滑块 `absolute` 却没写 `left-0`,会落回「静态位置」(按钮正中),
  再叠加 translate 就整个滑出轨道。护盾面板和组件管理页两处都受影响,已修。

## 四、定名 Mainbench

「Triforge」是 1.0.0 定的试水名,一直挂着「发帖前要认下来或换掉」的待办。这一版换掉它:
**产品名、仓库名、所有面向人的文案统一为 Mainbench。**

### 只动了显示层

1.0.0 立的两层结构在这里第二次兑现了 —— 改名只改 `ui/src/lib/brand.ts` 里的一行,
外加 `productName`、README、仓库地址这些人眼能看到的地方。

**内部 slug 仍然是 `workbench`**,一个字都没动:

| 身份 | 值 | 动了会怎样 |
|---|---|---|
| appId | `ai.iimos.workbench` | macOS 认为换了个应用,自动更新链断,已装的收不到更新 |
| userData 目录 | `~/Library/Application Support/workbench` | 设置、网页登录态(`persist:web`)、组件的钉全部归零 |
| localStorage 键 | `workbench.*` | 侧栏面板、宽度、草稿、主题全部重置 |
| 更新通道 | `dl.iimos.ai/workbench/mac-arm64` | 平台侧的路径,不在本仓库 |
| 遥测端点 | `api.iimos.ai/v1/workbench/t` | 同上 |

这些是身份不是名字。**换个叫法不值得让用户丢一次数据**,而且后两条根本不在这个仓库里,
改它得连 iimos 平台一起动。名字可以再换第三次,身份链只能断一次。

### 顺手修的

`ui/index.html` 的 `<title>` 还停在更早的 `Workbench` —— 1.0.0 改名时漏的,
开发态浏览器标签上一直显示错的名字。这次一并改对。

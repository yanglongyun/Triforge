这样解决了什么

竖排 + 全窗口高度:560px 高的窗口里,原生四个和底部加号 / 设置永远钉住,只有组件这一段滚动 (flex:1; overflow-y:auto,溢出时上下有渐隐提示)。能装的数量是横排的好几倍, 而且组件再多也挤不动原生入口。

顺带得到两个好处

① 活动栏与面板分离后,「收起侧栏」只收内容面板、图标条常驻;点当前图标一下就是收起, 这是 VS Code 用户的肌肉记忆。② 状态点上浮到图标上:会话有未读亮绿点、有应用在跑亮蓝点 —— 面板关着也看得见,这在横排挤压时代做不到。

代价

窗口最窄处要常驻让出 52px;现在「侧栏收起后标签栏挂汉堡按钮」那套逻辑要重做 (本方案里汉堡只管面板开合,不再是唯一入口)。窄屏 / 移动端竖排是否还成立要单独想一版, 大概率仍是抽屉 + 横排。
